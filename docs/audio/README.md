# Generated audio (MV-1134)

One sound (`UiClick`) is now generated by ElevenLabs instead of the procedural synth. The synthesised
sound stays as the permanent fallback for every cue that hasn't been generated — see
`SfxCueLibrary.ResolveClip`.

## Run it

```
"%UNITY_PATH%" -batchmode -quit -projectPath . -executeMethod MaxWorlds.Editor.Audio.ElevenLabsAudioGenerator.GenerateFromCommandLine -logFile Logs/elevenlabs_generate_unity.log
```

Or from the Editor: **MAX → Audio → Generate missing sounds**.

An entry in `Assets/_Project/Audio/audio_manifest.json` whose output `.wav` already exists is skipped,
so a re-run spends no credits. Pass `-regen <id>` to force one entry to regenerate.

## Key

`ELEVENLABS_API_KEY` env var if set, otherwise `C:\Dev\MAx CCs\secrets\elevenlabs_api_key.txt`
(trimmed). Never in the repo, never logged, never in a commit or a Jira comment.

## What was proven (7 Oct 2026)

- The dev PC can reach `api.elevenlabs.io`.
- The Creator plan's sound-generation endpoint accepted `output_format=pcm_44100` on the first
  request — the `pcm_24000` fallback was not needed.
- `UiClick` cost **6 credits** (0.116s after silence-trimming, from a 0.5s request).

## Reverting a cue to its synthesised sound

Delete a `.wav` under `Resources/Audio/Sfx` to return that cue to its synthesised sound.
